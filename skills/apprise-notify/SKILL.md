# 发通知

本机有一个常驻的 Apprise 网关（Docker 容器 `apprise`），把「发通知」收成一个固定 URL。
发一条 = 一次 HTTP POST：没有队列、没有模板、也没有送达确认。

## 环境

| 项 | 值 |
|---|---|
| 地址 | `http://127.0.0.1:8765`（只绑回环，本机可达） |
| 频道 | `info`（唯一一个 key） |
| 部署 | `~/ws/w/20261010-通知看板工具/apprise/` |
| 探活 | `curl -s http://127.0.0.1:8765/status` → `OK` |

**调用方不需要凭据**：token 由容器环境提供，不在请求里，也不在 agent 进程里。

## 发一条

```bash
curl -sS -X POST http://127.0.0.1:8765/notify/info \
  --data-urlencode 'title=构建完成' \
  --data-urlencode 'body=**3 个包**，用时 42 秒' \
  -d 'type=success'
```

成功返回 **200**，响应体是 Apprise 的日志文本，末行形如 `Sent ... notification to ...`。

**正文按 markdown 处理**（容器里 `APPRISE_DEFAULT_FORMAT=markdown`），所以 `**加粗**`、`- 列表`、`` `代码` `` 都能渲染。要原样显示星号，显式传 `-d 'format=text'`。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `body` | ✔ | 正文（markdown）。建议 4K 以内，太长会走别的形态甚至丢内容 |
| `title` | | 标题 |
| `type` | | `info`（默认）/ `success` / `warning` / `failure`。**只影响图标，不是优先级** |
| `format` | | `markdown`（默认）/ `text` / `html` |

## 返回码

| 码 | 含义 | 该怎么办 |
|---|---|---|
| 200 | 全部送达 | 正常 |
| 424 | 未全部成功：端点失效 / token 失效 / 超时 | 告诉用户，别静默重试 |
| 400 | 参数错（多半是缺 `body`） | 修调用 |
| 连不上 / 5xx | 网关自身故障 | 见下 |

## 网关挂了怎么办

先探活：`curl -s -m 3 http://127.0.0.1:8765/status`（3 秒内没有 `OK` 就是不通）。

不通时**不要自己改网关配置、不要敲一堆 docker 命令试**，去工作区读入口文档：

```
~/ws/w/20261010-通知看板工具/README.md
```

那份 README 的「兜底」一节写明现在该改走哪条临时通道，以及这个网关该怎么修——工作区里还有完整的部署与运维文档。临时通道发完通知、事情办完，就把这个故障原样报给用户，由他决定何时修。

## 约定

- 主要是**写入**。除非用户明确要求，不要主动去读历史通知。
- 同一件事不要反复推送；不要在循环里逐条发。
- 长内容别塞通知：超过一两屏、要配图/表格/留档时，改用 `mail-notify` 发邮件。
- `type` 不是优先级。要让通知在手机上弹得更凶，只能改端点配置里的 `priority`，调用方定不了。
